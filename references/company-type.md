# 按价值来源选择估值方法

深度分析、早盘预案和尾盘决策共用同一流程。先识别股东收益的主要来源，再选估值方法、做压力测试，最后按 [决策规则](decision-rules.md) 判断价格偏离和能否执行。经营形态、行业标签、估值方法和用户建仓风格各有独立用途。

## 1. 识别收益来源与适用数据

1. 判断未来可分配现金从哪里来。记录近年财报与可验证经营指标，说明哪些驱动影响收入、利润、现金回收、资本需求或价值实现。区分已实现、已签约、指引、一致预期和分析假设。
2. 用至少两项有来源的证据解释主导机制，给出一条最可能推翻判断的证据。类型随业务结构和盈利机制改变；单期异常、股价回撤和一次预期修订只触发复核。无合适形态时可留空；跨业务时先确定主导来源，再决定是否分部估值。
3. 选择能解释可分配现金、净资产或权益索取权的主方法。可比倍数要求业务结构、资本强度、周期和会计口径可比。若主方法缺少关键输入，说明缺口与估值置信度；有条件才给出敏感性区间。
4. 独立整理可验证驱动与估值复评条件。结论来自证据，用户补充的事实可纳入验证，用户偏好用于执行层。

## 2. 方法、压力情景与改判证据

| 价值来源或经营形态 | 主方法与交叉验证 | 保守情景、偏乐观情景与关键复评证据 |
|---|---|---|
| 缓慢增长 `slow_grower`、成熟分红业务 | 稳态可分配现金流 `cashflow` 或股息率 `dividend_yield`。同口径历史 PE `pe_band` 辅助 | 测销量和提价、维护资本开支、分红覆盖。分红依赖举债时重算现金能力。 |
| 稳健增长 `stalwart` | 正常化盈利与同口径 PE 区间，或 `cashflow`。用自由现金流收益率、增量资本回报交叉验证 | 测份额、利润率、再投资回报和经营现金转化。份额与现金回报持续背离时复评。 |
| 快速增长 `fast_grower` | `cashflow` 按单位经济、再投资和增长衰减建模；成熟盈利阶段可用 `pe_band`。PEG `peg` 用于正且可比的盈利增速的旁证 | 测增长放缓、毛利率、获客回收、稀释。用反向 DCF 检验现价要求的增长与回报。 |
| 周期 `cyclical` | 用完整可比供需周期的正常化盈利 `normalized_eps`；有足够可比长期样本时用 `cape_pb`，资产重置或成本曲线交叉验证 | 结合成本曲线、产能和库存，测景气低位与供给收缩。盈利高点的低 PE 不构成折价证据。 |
| 困境反转 `turnaround` | 先测生存与再融资，再用 `normalized_eps` 或 `cashflow` 测修复和失败；需要时以清算价值交叉验证 | 检查现金跑道、债务到期、营运资本、稀释以及反转里程碑。区分行业景气抬升和公司自身改变。 |
| 隐蔽资产 `asset_play`、控股或多业务 | 可处置资产用 `rnav`；现金流来源差异显著且能拆分时用 `sotp` | 测实现期、税费、少数股东、控股层净债务和资本开支。剔除内部交易和重复计值。 |
| 银行 | `pb_roe` 使用可持续 ROE、权益成本、合理增长与资本约束；可分配股息交叉验证 | 压测息差、信用成本、拨备、资本充足率和分配能力。信用损失集中暴露或资本约束改变时复评。 |
| 保险 | 可比且可验证的 `embedded_value`；披露不足时用情景化可分配现金流 `cashflow` | 测投资利差、退保、赔付和偿付能力。核对内含价值假设及资本释放，区分寿险与财险。 |
| 项目驱动、未形成稳定利润的研发或许可 | `rnpv` 按项目、阶段和地区拆分预付款、里程碑、特许权使用费及研发成本，结合净现金和融资稀释 | 测条件成功概率、上市时间、现金回款、现金跑道和债务偿付。按协议判断损益确认与实际现金；共享风险需联合做情景。关键试验、监管节点及交易对手履约时复评。 |
| 指数 ETF | `index_earnings` 用指数可比盈利、成分权重和利润率估值，用基金 NAV/IOPV 和跟踪偏离判断执行 | 压测头部成分、盈利修订、指数换仓与估值回归。检查溢折价、流动性及数据时点。 |

方法选择示例：现金流可预测的商业模式可以用现金流模型；不同业务有不同价值机制时，可以在分部内用不同模型，再归并为每股基础价值。税费、债务、稀释和同一里程碑的现金流只计一次。已经计入基础价值情景的增量，可在期权清单里说明范围，但不得重复定价。

## 3. 落地到台账与统一执行

- 报告记录主要价值来源、模型与交叉验证、基础价值低中高三档、关键输入及日期、反方证据和改判条件。高估减仓用偏乐观情景复核，低估买入用保守情景验证。区间与模型误差重叠或关键数据缺失时给出当前持有或等待，以及下一次判断的具体条件。
- `set-type --primary <形态或 unclassified> --model <上表方法> --basis ... --counter ...`。选模型时显式传 `--model`；省略时沿用同形态的已存方法或历史兼容默认值。旧 `peg` 档案可读写，复核时说明它是否有可独立支撑的主模型。 `confirmed` 记录用户确认状态，估值置信度由证据决定。
- 变更已登记形态或方法时提供 `--reason`，用新方法重算基础价值三档与四锚并一次提交 `set-thesis`。完成前，脚本拦住买入和估值透支减仓；证据充分的基本面减仓按统一规则判断。关键数据、期权和财务条件适用各标的同一复评流程。
- 用户预算、建仓风格、整手和订单校验沿用 [决策规则](decision-rules.md)。同类资产使用同一判断流程，触发阈值以各自模型的敏感性、财务约束和数据波动确定。
