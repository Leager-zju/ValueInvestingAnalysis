# 决策规则：建仓策略 / 波段策略两套并行

**读法**：先看第 5 节做分流，判断这次分析问的是"建仓"还是"波段"，然后只读对应的策略块。
第 6 节（底仓）与第 7 节（波段）是两套**互不引用**的规则，不要混着用。

---

## 1. 无状态原则（所有规则的前提）

**每一次分析，只基于"此刻的状态"，不看"之前几天做了什么"。**

### 1.1 可以进入决策的状态

| 类别   | 内容                    |
| ---- | --------------------- |
| 价格状态 | 当前价、当日量价、所处估值区间       |
| 持仓状态 | 总股数、底仓/波段划分、券商成本、可用资金 |
| 估值状态 | 四锚、基础价值三档、期权清单        |
| 因子状态 | 各驱动因子的最新读数与新鲜度        |
| 画像参数 | 全局 2 个 + 标的 2 个        |

### 1.2 状态本身必须是真的

无状态不等于"随便传个价格"。当前价格时点若偏离今天超过 1 天，`calc` 会返回 `price_warning`；价格与成本相差 80% 以上时也会提醒核对——**用错误的状态算出的结论，比没有结论更危险。**

### 1.3 不进入决策的

- 上次什么时候交易、上次的成交价是多少
- 上次的结论对不对、有没有被市场打脸
- 已浮亏多少天、空仓多久没动手
- 历史 K 线的具体形态（除当日的量价定性外）

### 1.4 为什么必须无状态

1. **历史动作是结果，不是依据。** 用"距上次 3 天"约束今天的决策，等于让昨天的操作决定今天的对错。
2. **可复现。** 同一天、同一价格、同一持仓，任何人都应该得出同一个结论——否则规则就变成"看心情"。
3. **分批节奏用价格表达，不用时间表达。** 价格不变就不该加仓；价格变了，天然就该分批。时间驱动（"每 10 日一轮"）会在价格纹丝不动时逼你加仓，这是规则设计上的错误。

### 1.5 唯一的例外：同一次决策的内部配对

波段的两端价格（卖出价 ↔ 买回价、买入价 ↔ 卖出价）是**单次操作内部的配对参数**，必须一次性给出、不可拆成两次独立决策。它不是跨日历史依赖，而是同一笔逻辑的完整性要求。

## 2. 政策与政治事件的处理

宏观政治事件（选举、关税、制裁、法案）可以大幅影响股价，但**不能直接进估值**：

1. 只能登记为 `category: "policy"` 的因子，必须带传导链（channel）、方向、窗口（≤36 个月）与验证点；写不出就说明它只是情绪。
2. **只能压低买价，不能抬高卖价**：用它下调 `core_entry` / `deep_value`（提高安全边际），不得用它上调 `fair_high` / `overvalued_above`。
3. **不得用当天涨跌反推原因**。因子必须在事件发生时登记，之后由 `verifiable` 里的数据验证，而不是拿股价验证股价。
4. 政策因子 `level` 不能是 `core`，不进入期权 payoff 计算（期权必须有可计量的每股盈利增量）。
5. 窗口到期未兑现的自动作废，不参与判断。

一句话：**政策消息让股票更便宜，不会让公司更值钱。**

## 2.5 全球利率（10 年期美债）的处理

利率与政策都会动折现率，但**处理方式不同**，混用会出错：

| | 政策因子 | 利率因子 |
|---|---|---|
| 登记 | `category: "policy"`，带窗口与验证点 | `category: "rate"`，带 `beta_rate` 与 `rate_baseline` |
| 方向 | 只能压买价、不能抬卖价 | **可双向**修正 `base_*` |
| 作用点 | 只下调 `core_entry` / `deep_value` | 通过倍数修正系数 `k` 改 `base_*`，四锚再派生 |

四条执行规则：

1. **利率只改倍数，不改盈利**：不得因为美债变动去调整 EPS、营收或订单假设；也不得进入期权 `payoff` 的盈利项。
2. **必须记基准**：`valuation.rate_baseline = {yield, date}` 缺失时，只做定性说明，不许动锚。修正后立即把基准更新为当前值，避免同一段变动被反复计价。
3. **异动要单列一行**：单日 10Y 变动 **≥ ±15bp**，或相对基准累计 **≥ ±25bp** 时，当日早盘/尾盘报告必须写一行「利率异动」——写清变动幅度、对 `β_rate` 的含义、是否触发倍数复核。**没触发也要写"Δ 不足 25bp，本轮不改锚"**，避免"改了没说"。
4. **不许拿它当买卖理由**：利率上行不是卖出理由，利率下行也不是买入理由。它只改变"哪个价位算便宜"，不改变"这家公司好不好"。**减仓仍然只有两类理由（基本面恶化、估值透支）。**

一句话：**利率决定你出什么价，不决定你要不要这家公司。**

## 3. 同日多份报告冲突怎么消解

同一天可能生成早盘（open）、收盘（close）、深度（deep）三份报告。它们读同一份档案，但**深度复核会改写档案本身**（重算基础价值与四锚），所以冲突几乎都来自这一点。

先分清三种不一致，解法完全不同。

### 3.1 区间判断不一致 —— 锚被改过

**根因**：收盘报告 14:30 生成时用的是当时的锚；深度复核 20:00 重算了锚，那么**收盘报告的区间判断在锚更新那一刻就过期了**。

规则：

- **锚只有一个来源**：`portfolio.json` 的 `valuation`。任何报告都不得自带一套锚，也不能"另存一份旧锚做参照"。
- 每份报告页头写一行：**锚版本 `YYYY-MM-DD HH:MM`**（取自 `calc.anchor_revision.revised_at`）。
- 冲突时**以最后生成的那份为准**——不是"谁更对"，而是"谁用的是最新状态"。
- 深度复核若改动了锚，**必须单列「下游影响」**：今天已发出的早盘/收盘报告里，哪些区间判断、哪些动作因此失效。

### 3.2 评价不一致 —— 质地分、性质、基础价值

- 性质改判只能由 `set-type` 完成且必须带 `--reason`；深度复核**只建议、不直接改**，所以不会出现"两份报告各说一个性质"。
- 质地分与基础价值同理：深度复核写入档案后，之后生成的收盘报告读到的就是新值。先后颠倒时仍是 3.1 的时序问题。

### 3.3 策略不一致 —— 风格、窗口、波段仓

- 这些属于**标的画像**，深度复核只建议不改。
- 若两份报告给的建仓风格不同，先查 `calc` 返回的 `trading_profile.source`：
  · 显示 `global` → 说明这只票没设标的画像，用的是全局默认，容易与其他标的混用；
  · 显示 `holding` 但值不同 → 其中一份用了旧画像，按"最后生成的为准"。

### 3.4 硬规则

1. 同一标的同一槽位的报告，**后写覆盖先写**（文件层面天然如此）。
2. **不同槽位之间不互相引用历史结论**。冲突时不问"上次怎么说"，只问"现在的事实是什么"——这是无状态原则的直接推论。
3. 深度复核结束后刷新 `index.html`，页面上带各报告时间，用户可自行判断哪份最新。

## 4. 两种对称的错误

| 错误       | 表现                | 后果                              |
| -------- | ----------------- | ------------------------------- |
| 追高       | 因为"怕再涨"在透支区买入     | 亏钱，但看得见                         |
| **永远不买** | 单点挂一个深度折价，价格永远不回来 | 亏损看不见，却同样确定：**0% 仓位 = 放弃了全部上行** |

框架必须同时防这两种。判断"贵不贵"只是上半场，判断"以什么路径拿到仓位"是下半场。

## 5. 先分流：本次分析问的是「建仓」还是「波段」

**这是全流程的第一步。判断完只读对应章节，不要带着一个 block 的条件去算另一个 block。**

### 5.1 看持仓，定路径

| 持仓状态 | 本次分析的性质 | 读哪几节 |
| --- | --- | --- |
| 空仓，或底仓未建满（已投 ≤1/3） | **建仓** | 只读**第 6 节** |
| 底仓已建满（已投 >1/3），波段仓 = 0 | **可能波段** | 先查 6.1 有没有减仓理由；没有就只读**第 7 节** |
| 已划分波段仓（`swing_shares > 0`） | **波段** | 同上，重心在**第 7 节** |

`calc` 里的判断依据：`invested_ratio_pct`（预算已用）、`position_split.swing_shares`、`matrix.action`。

### 5.2 已建仓的，先排除减仓，其余一律走波段

对已建仓的标的，分析顺序永远是：

1. **先问：6.1 的两类减仓理由成不成立？** 基本面恶化（A1–A7）或估值透支（B 三条同时满足）。
2. **成立** → 按 6.1 处理，动底仓。这是唯一该动底仓的情形。
3. **不成立** → **默认动作是第 7 节的波段策略，不是"什么都不做"，也不是"等一个更低的建仓价"。**

> 最常见的误判：底仓建满后 `matrix.room_amount` 归零，分析就停在"不能再加仓"，把"没有建仓额度"当成"没有事可做"。**底仓额度耗尽不等于无事可做——它只意味着从此刻起，能动的是波段仓。**

### 5.3 不许跨 block 借条件（三条禁令）

1. ❌ **不许用建仓通道（A/B/C、`deep_value`、`core_entry`、`zone_cap`）筛选波段买点。** 波段买入价由"计划卖出价 ÷ 1.05"反推，与建仓价无关。
2. ❌ **不许用 `matrix.room_amount` 回答波段能用多少钱。** 那个字段是底仓的账；波段的钱看 `calc.swing.buy_power`。
3. ❌ **不许用预算使用度（1/3、2/3）描述波段状态。** 波段是独立资金池，不设预算刻度，只问"这笔卖掉了没有"。

反过来也成立：**波段规则不能拿来给底仓找买点。** 波段仓（= 总持仓 − 底仓）不是底仓的加仓额度，波段赚到的价差也不构成底仓加仓的理由。

### 5.4 分流结果怎么落到输出里

报告必须把这个判断写在显眼处，例如：

> **本次性质：波段**（底仓已建满 57.02%，6.1 两类理由均不成立）
>
> 底仓：可加 0 元（`matrix.room_amount`）
> 波段：可用 21,492.40 元（`swing.buy_power`）

三条信息必须各占一行，不许合并成一句"还能加多少"。

## 6. 底仓策略（长期敞口）

**底仓回答的是：这个价位值不值得新增/保留长期持仓。**

底仓的进场由**估值锚**决定，额度由**预算矩阵**决定，方向只有买（卖出需 6.1 的理由）。它不看 `swing.buy_power`，也不因为波段做过几轮而改变——波段赚到的钱不进底仓的建仓额度。

### 6.1 减仓与清仓：只有两类理由

#### A. 企业基本面恶化（满足任一即触发复核，复核后确认则减仓/清仓）

| #  | 可验证信号    | 量化口径                                          |
| -- | -------- | --------------------------------------------- |
| A1 | 盈利能力中枢下移 | ROE(扣非) 连续 2 个年度下降且最新一年 < 10%（或低于行业前 50% 分位）  |
| A2 | 盈利质量崩塌   | 经营现金流/净利润 < 0.5 且持续 2 期，或应收增速 > 收入增速 20pct 以上 |
| A3 | 护城河被侵蚀   | 毛利率连续 3 期下滑累计 ≥ 5pct，且份额或单价同步下滑               |
| A4 | 资产负债表恶化  | 有息负债/EBITDA > 3，或短期借款激增覆盖不了利息                 |
| A5 | 投资逻辑被证伪  | `thesis` 中列明的关键假设出现反例（政策废止、核心产品降价、大客户流失）      |
| A6 | 治理风险     | 财务造假、审计非标、大股东大额减持/质押爆仓、重大处罚                   |
| A7 | 分红能力丧失   | 原本稳定分红，突然取消或大幅下调且无资本开支解释                      |

**必须写成"信号 + 数据 + 报告期"三段式**。
例：`A3 毛利率 〔T-2〕 x% → 〔T-1〕 y% → 〔T〕 z%，累计降幅未达 5pct 阈值 → 观察`。

#### B. 估值透支（同时满足）

1. 价格 ≥ `overvalued_above_price`（**该线已含期权全额，不要用基础价值上沿代替**）；且
2. 盈利预期没有同步上修（`data_consensus` 未来两年净利预测未上调 ≥10%）；且
3. 企业质地评分未上升。

满足时：透支线以上减 1/3；超出透支线 20% 以上减至 1/2 预算；基本面同时走坏则清仓。

**注意**：如果期权正在兑现（如注入已落地、新产能已投产），先更新 `option_value` 与锚定价，再判断是否透支。用未更新的透支线去卖一家刚变好的公司，是另一种踏空。

#### C. 明令禁止的卖出理由

- 短期下跌、连续阴线、浮亏、成本线心理位
- 大盘/板块下跌、"情绪差"
- 未证实的传闻、社交媒体观点
- "已经涨很多了先落袋"（除非满足 B）
- 非投资因素（用钱请单独说明，不伪装成投资决策）

出现上述理由而建议卖出底仓的输出**一律视为错误**。

### 6.2 建仓通道（按价格位置分三档）

**本节只服务"新增长期持仓"。价格必须落在 A/B/C 某一通道内，这条对波段不适用（波段见第 7 节）。**

| 通道        | 价格条件                                                               | 单笔上限                          | 前置条件                                               |
| --------- | ------------------------------------------------------------------ | ----------------------------- | -------------------------------------------------- |
| A 低估区建底仓  | `deep_value ≤ P ≤ core_entry`                                      | **可用资金全额**（仅受账户可用资金约束）        | 质地 ≥6，无 A 类信号                                      |
| B 深度低估加仓  | `P < deep_value`                                                   | **可用资金全额**                    | 同上，且锚定价未被下修                                        |
| C 时间换价格底仓 | `core_entry < P ≤ 合理区下 1/3 段`（= core + 0.33×(fair_high−core)，比例可调） | 可用资金 **1/2**（与其累计上限一致） | 踏空厌恶=high、质地 ≥8、**已登记上行期权**、价格每再下移 5% 加一轮、累计 ≤ 1/2 |

> **单笔操作不设通道比例上限。**
> A/B 单笔上限 = 该标的可用资金全额；C 单笔 = 可用 1/2，因为它的**累计**上限就是 1/2，单笔若放开到全额会与累计自相矛盾。
> `check-order` 会在单笔 > 50% 可用时输出 `concentration_note`（提示"分批节奏将被一次性消耗"），**只提示、不拦截**。
> 始终生效的约束：累计 ≤ `budget`、C 通道累计 ≤ 可用 1/2、买入金额 ≤ 可用资金、不融资不加杠杆。

规则：

- 通道 A/B 是默认路径；通道 C 是**为"价格长期不回落"准备的合法路径**，不是追高的借口。
- 通道 C 的窗口刻意**不收在整个合理区**，只收在下部 1/3：既缓解踏空，又避免在合理区上半部把仓位堆满。比例由 `entry_zone_ratio` 控制（0=只在底仓线，1=整个合理区）。
- 通道 C 的**节奏**仍然更慢（价格每再下移 5% 才加一轮、累计 ≤ 1/2），因为它放弃了折价保护，只能用时间和节奏来换；但**单笔金额**不因此再单独收紧。
- 三个通道累计不得超过该标的的 `budget`。**分批节奏只看价格**：价格每再下移 5% 才加下一轮；价格不动就不加（无状态原则，见第 1 节）。
- **价格在透支区一律不新增**，无论哪个通道。
- 任一通道执行前必须复核：质地未降、无 A 类信号、锚定价未下修、期权清单是最新的。

### 6.3 等待纪律

- 空仓不等于安全，空仓是一个 0% 的仓位，也有成本和风险。
- 若标的质地 ≥8 且期权价值占基础价值 ≥10%，长期只在深度折价等成交，期望上是不划算的：等到的概率低，等不到的机会成本高。
- 但**不允许**因为"怕再涨"跳过通道条件直接买。怕，不是理由；机会成本，才是理由，而且必须量化。
- **给出的任何买点都必须能追溯到 `calc` 字段**（`deep_value_price` / `core_entry_price` / `entry_plan.time_entry.zone_cap`）。不许即兴给一个数。
- **距现价跌幅 >15% 的买点必须标注「尾部机会，不是计划中的下一步」**，并附可达性依据（近 60 日区间是否覆盖，或首达概率）。把深跌买点写成"该做的动作"，等于让用户空手等一件大概率不发生的事。
- 若三通道全部不可达，如实写"当前无合法建仓点"，并说清是哪个门槛锁住的、什么事实会让它打开；**不要顺手把波段额度当成建仓额度来用**。

### 6.4 底仓买入的三条附加校验

除第 9 节通用硬约束外，底仓买入还要单独满足：

1. **价格落在 A/B/C 某一通道内**（通道 C 另需满足其全部前置条件）。
2. **限价 ≤ `fair_high_price`**（该线已含期权 ×0.6）；无锚定价禁止买入。
3. **建仓额度取自 `matrix.room_amount`**，不用 `available_cash`，也不凭记忆套矩阵。

### 6.5 锚复评触发（防「买入真空区」踏空）

**问题**：A/B/C 三条通道全部由价格触发，`core_entry ~ fair_high` 之间没有任何买入入口。价格一旦在这个区间启动主升浪，框架会一动不动。这就是「买入真空区」。

**解法不是调高买点，是让锚先动**。追高买点没有退出依据；而因子兑现 → 锚上修 → `tier1` 自随之上移，价格不动、买点就够得着了。这是唯一不违反入场纪律的防踏空机制。

#### 6.5.1 触发器怎么写

每条触发器写在 `valuation.reanchor_triggers`，用 `set-reanchor --code C --file triggers.json` 写入（按 `id` 合并）。

| 字段 | 要求 |
| --- | --- |
| `id` | 稳定标识，`--observe` 靠它定位 |
| `driver` 或 `all_of[].driver` | **必须是 `drivers.items` 里已登记的因子名**，写错等于没设防（`selfcheck` 会拦） |
| `op` / `value` | 只支持 `>=` / `<=`。阈值必须是绝对读数，不是变动幅度 |
| `observed` / `observed_date` | 当前读数与日期，由 `--observe id:因子名=数值` 回填；不复用 `latest_value`（那是给人读的描述文字，不可计算） |
| `reanchor` | 触发后要重评哪个锚：四个锚名之一，或 `all` |
| `direction` | `up` / `down` / `review_only` |
| `basis` | 阈值的推导依据。**写不出依据的阈值不许写进触发器** |

多条件用 `all_of`（AND）。**这不是为了严谨，是为了防噪音**：单看一铵涨价会被硫磺成本吞掉，必须「售价上 + 成本不失控」同时成立才算价差走阔。

事件型用 `{"type": "event", "due_date": "YYYY-MM-DD", "reanchor": "all"}`：到期即强制重评。**到期没消息也是一种信息**，它必须变成一次重评，而不是无限期挂在「待通知」上。

#### 6.5.2 硬规则

1. **只有 leading 因子可当触发器**，`coincident` / `lagging` 只能用于确认（与第 1 节无状态原则一致：已发生的事不能预测）。
2. **双向都要设**。只设上修等于单向乐观：周期品下跌时会被「锚还在原处」安抚住。
3. **触发即失效**：`calc.reanchor.triggered` 非空时，任何沿用旧锚算出的买点自动作废。`check-order` 会给买入加一道闸门，须先 `option + set-thesis` 重算四锚，再带 `--anchor-reviewed` 下单。
4. **重跑锚后必须同时重设触发器**：阈值是相对旧锚的盈利假设写的，锚变了阈值大概率也要变。改完用 `--observe` 回填新读数，否则触发器会永久挂着、把所有买单拦死。
5. **触发器不改通道**。锚上修只让 `fair_high` 更真实，不解除质地分、期权、矩阵额度的任何一道关。质地 4 分的标的，锚上修到天上也仍然不能买。

#### 6.5.3 与「怕踏空」的区别

| 情形 | 动作 | 性质 |
| --- | --- | --- |
| 因子越过事先写死的阈值 | 重跑锚 → 买点上移 | 合法 |
| 价格涨了、因子没动 | 不动 | 这是追高，不是防踏空 |
| 锚已上修、价格仍在旧锚区间 | 按新锚重新判区间 | 合法 |

第三行是最容易被忽略的一格：**锚先动、价格后到**，才叫提前布局；价格先动、锚后追，那是事后合理化。

## 7. 波段策略（临时敞口）

**波段回答的是：这一批筹码过几天要不要出来。**

波段是**独立资金池**，不产生长期敞口，因此**不受建仓通道与预算矩阵管辖**。它的买入价由出口反推，额度来自可用资金；**规模不设比例上限**——波段仓 = 总持仓 − 底仓，由分桶自动派生（见 7.2）。方向双向。

### 7.1 底仓与波段是两套账，不许互相套用

这是本节的第一原则，也是最容易混淆的地方。两者回答不同问题，所以进场条件、额度来源、风险刻度全都不能共用：

|       | 底仓（长期敞口）                                              | 波段仓（临时敞口）                       |
| ----- | ----------------------------------------------------- | ------------------------------- |
| 回答的问题 | 这个价位值不值得**长期持有**？                                     | 这一批筹码**过几天要不要出来**？              |
| 进场条件  | 必须用估值锚：≤ `deep_value` / ≤ `core_entry` / ≤ `zone_cap` | **不看任何建仓价位**。买入价由"卖出价 ÷1.05"反推  |
| 额度来源  | `calc.matrix.room_amount`（价格位置 × 预算使用度）               | `calc.swing.buy_power`（该标的可用资金） |
| 方向    | 只有买（卖出需 6.1 的理由）                                      | **双向**：先卖后买、先买后卖都合法             |
| 规模刻度  | 预算比例（1/3、2/3、上限） | **不设刻度**：波段仓 = 总持仓 − 底仓，自动派生 |
| 退出条件  | 基本面恶化 / 估值透支                                          | 到达计划价即走，**没有第二个理由**             |
| 持有期   | 3 年以上                                                 | 几天到几周                           |

**下面三句话都是错的，见到就要纠正：**

1. ❌「波段仓也要等到 `core_entry` 或 `zone_cap` 才买」——底仓建完后再等低估价，等到的不是波段，是第二份底仓。
2. ❌「`matrix.room_amount = 0` 所以波段也不能买」——`room_amount` 是**底仓**的账，波段用的是 `swing.buy_power`，两者经常一个是 0、一个是全部可用资金。
3. ❌「波段只能先卖后买」——先买后卖同样合法，判据是**有没有写下来的出口**，不是方向顺序。

**必须承认的后果**：底仓额度耗尽（`room_amount = 0`）时，波段额度**仍然存在**。这不是漏洞，是设计——它意味着你可以在"不再新增长期持仓"的前提下，用存量资金做高抛低吸。**波段赚的是价差，一轮走完敞口回到原点；它不改变长期持仓，也不降低底仓成本以外的任何风险。**

### 7.2 仓位分桶：用一条分界线替代交易流水

本技能**不记录交易流水**（`portfolio.json` 只存最新成本）。要在不记账的前提下校验波段纪律，办法是只记一条分界线：

```bash
python <skill>/scripts/portfolio.py set-profile --code C --core-shares <底仓股数>
# 结果：底仓 = 总持股 − 300，波段仓 = 300
```

- **底仓**：只在 6.1 的理由成立时动，**永不参与波段**；
- **波段仓**：双向使用——先卖后买时卖在"总持仓 − 底仓"之内，先买后卖时买入会让这条线**自动右移**（因为总持仓变多、底仓不动），**不需要事后改任何东西**；
- 换仓、加仓后**重设一次底仓线**即可，不需要记录任何一笔成交。

> **分桶只问底仓。** 波段仓没有比例上限——比例既不是钱的口径，也不是风险的口径，只是把波段塞回底仓刻度的尺子。两条等式是：**波段仓 = 总持仓 − 底仓**；**波段交易的钱 = 该标的可用资金**。先卖后买能卖多少看 `sellable_shares`，先买后卖能买多少看 `can_open_shares`，后者只由可用资金决定，不乘任何比例。

分界线写在 `holding.swing_shares`，`calc` 会返回 `position_split`（底仓/波段仓）与 `swing`（波段独立额度），`check-order` 据此校验。

### 7.3 形态一：先高后低（先卖后买）

1. **前提**：波段仓 > 0（= 总持仓 − 底仓，自动派生），**标的质地 ≥8**，无 A 类信号。
   · 质地 <8 的标的默认不开放波段（质地低意味着"错了不容易看回来"，做 T 只会把错误摊得更久）。用户如明确要求可显式覆盖——用 `set-profile --swing-quality-override on`，`calc.swing.reason` 会写明"由用户显式覆盖"，覆盖须同时写进当次报告，**覆盖只解除这一条门槛，不解除其余各条，也不改变质地评分本身**；
2. **卖出触发必须是位置，不是情绪**：价格进入偏贵区（> `fair_high_price`）或量价出现「高位放量滞涨」，且盈利预期未上修；
3. **卖出股数 ≤ 波段仓**（脚本强制），底仓不动；
4. **买回价 ≤ 卖出价 × (1 − 5%)**（`--buyback-price` 强制填写并校验），且 **≤ 卖出当日的 `fair_high_price`**——**不要求落回建仓窗口（`zone_cap`）**。
   · 理由：**建仓窗口回答"这个价位值不值得新增持仓"，买回回答"要不要把刚卖的同一批筹码买回来"，两者不是同一个问题。** 把买回绑到窗口，会在底仓成本高于窗口时让回补永久不可行——波段退化成单向减仓。买回的上限应当是「还值得持有」的边界（`fair_high`），而不是「值得建仓」的边界；
   · 5% 的价差门槛保留：扣掉双边费用与滑点后仍然太小，且容易制造"我在降成本"的错觉；
   · **必须承认**：买回只降低账面成本，**不改变持仓敞口**——9,000 股还是 9,000 股。降成本 ≠ 降风险；
5. **买回股数 ≤ 上一轮卖出股数**，买回金额 ≤ 上轮卖出回收金额——不得借波段之名把仓位加上去；
6. **不设交易频次上限**（投资者有充足时间投入）。但"高频"不能替代"有价差"：每一轮仍须独立满足全部条件，不因为"最近做过"而放宽；
7. **买回后波段仓自动回升**（总持仓增加、底仓不动），不需要重新划仓；但买回股数仍 ≤ 上轮卖出股数——不得借波段之名把底仓也调上去；
8. **卖出前就写好放弃条件**：若价格不回落、继续上涨，**不得追高买回**。

### 7.4 形态二：先低后高（先买后卖）

底仓建满之后，「只有在低估区才允许买」这条规则就不再适合管波段了：此时再等一个低估价，等到的不是波段仓位，而是**第二份底仓**——它要占用长期敞口，还要占用矩阵额度，等于把波段做成了加仓的替身。

所以波段仓的买入**不受建仓通道、不受矩阵 `room_amount` 限制**。它不占用长期敞口，因此不该被长期敞口的规则管。取而代之的是五条自证条件，每一条都由 `--swing-open` 强制校验：

| 条件                     | 门槛                       | 为什么                          |
| ---------------------- | ------------------------ | ---------------------------- |
| 必须给出计划卖出价              | `--target-sell-price` 必填 | 不给卖价，这就只是一笔加仓，请走 6.2 |
| 卖价 ≥ 买价 × 1.05         | 5% 价差                    | 覆盖双边费用与滑点，并留出踏空风险的补偿         |
| 卖价 ≤ `fair_high_price` | 不指望卖进偏贵区                 | 卖出目标必须是"还值得持有"的边界内，否则是在赌估值泡沫 |
| 买价 ≤ `fair_high` ÷ 1.05   | 价格闸门                     | 你要的卖价（买价×1.05）必须仍落在合理上沿之内；否则这笔交易在规则上根本不可能成立 |
| 买入金额 ≤ 该标的可用资金         | 不融资、不挪用别的票的钱             | 波段不创造新钱，但这是资金约束，**不是预算刻度**   |
| 无 A 类基本面信号             | `--fundamental-ok`       | 基本面恶化时任何买入都是错的，波段也不例外        |

**这些条件里没有一条是"预算使用度"。** 波段不看 1/3、不看 2/3、不看 `room_amount`、也不看"买后占总预算多少"——那些全是底仓的刻度。也不输出「买后占总预算百分比」：它在 `avail = budget − basis` 下与「金额 ≤ 可用资金」完全等价，只会把波段硬拉回底仓的账上。

**规模没有比例天花板。** 分桶只指定底仓股数，波段仓 = 总持仓 − 底仓自动派生。先卖后买能卖多少看 `sellable_shares`，先买后卖能买多少看 `can_open_shares`（= 可用资金 ÷ 一手价），**两者都不乘任何比例**。`swing_cap_shares` 字段不存在——看见它说明脚本版本不对。

**先买后卖还有一道价格闸门，最容易漏。** 买价 ×1.05 必须 ≤ `fair_high`，否则"要的卖价"被上限挡住，额度够、通道开、价差也算得出来，交易却根本不成立。反推出**允许的最高买价 = `fair_high` ÷ 1.05**（脚本字段 `buy_first_max_price`）。例：`fair_high` 44.71 → 闸门 42.581；现价 44.46 在闸门之外，所以这个价位上**先买后卖这一形态做不了**，只剩先卖后买（前提是已有波段仓可卖）。

两条形态的差别只在**入场时点**，不在纪律：

- **先高后低**：已有底仓浮盈 → 先卖波段仓 → 等回落买回。风险是"卖了不回落"，损失少赚；
- **先低后高**：判断当前价偏低 → 先买波段仓 → 等反弹卖出。风险是"买了不反弹"，损失真金白银，**所以它比先卖后买更需要纪律**——5% 价差、`fair_high` 上限、买价 ≤ `fair_high`÷1.05 三条一条都不能少。

### 7.5 明确禁止：没有卖出计划的"波段"

旧判据是「波段先卖后买，摊薄先买再买」，**这个说法已被先买后卖通道推翻**——顺序不决定性质。正确的判据是：

> **有没有一个写下来的、高于买价 5% 以上的卖出价？**
> 有 → 波段（不论先卖还是先买）。
> 没有 → 摊薄加仓。下跌途中补仓拉低均价属于这一类：它把问题从"买贵了"换成"预算提前用光"——均价降了，但投入的钱更多了，亏损的绝对额也更大。

一句话：**区分波段与摊薄的不是方向，是有没有出口。**

> **但也不要用「顺序决定性质」去论证这条规则——那是错的。** 从终态看，`26.51 卖 300 → 25.18 买回 300` 与 `25.18 买 300 → 26.51 卖 300` **完全等价**：终态都是 1,100 股、成本基数相同、现金净流入相同。两者只是同一笔现金流的两种顺序，差别只在中途持股数。
>
> **这个差别不是"越界"，别把它写成越界。** 波段是独立资金池，**不存在 2/3 界**——2/3 是底仓的预算刻度，跟波段一分钱关系都没有。
> 波段唯一要盯的是：**这笔仓位有没有按计划卖掉**。卖掉了，账就平了；卖不掉（价格没到 `--target-sell-price`），它就从"临时敞口"变成"长期敞口"——**那一刻它不再是波段，而是一笔没有出口的加仓**。报告该写「这笔波段尚未闭环」，不是「越过了 2/3」。
>
> **两套规则的分界是敞口意图，不是交易方向：**
> - 想让这笔钱长期留在里面 → 加仓，受矩阵管、受 `room_amount` 限制，无出口；
> - 想让这笔钱过几天再出来 → 波段，受本节管、必须有 5% 以上的出口。
> 同一笔单不能既享受波段的通道豁免、又指望它长期持有。**申报时选一条，事后不许改口。**

### 7.6 波段的真实代价（必须承认）

波段能修复成本，但会制造另一种风险：**卖出后不回落，就变成踏空**。所以：

- 规模要有节制（**先卖后买不超过波段仓，先买后卖不超过可用资金**）——它的目的是"降成本"，不是"增收益"；
- **越厌恶踏空的人，波段仓位应越小**。把"降成本"当成主要收益来源，方向就错了；
- 波段失败（没买回）时，损失的是"少赚"，不是"亏钱"；不要因为不甘心而追高。
- 波段不改变长期持仓，也**不降低底仓的风险**——它只改账面成本和现金流。

### 7.7 记录方式（设计限制，如实说明）

本技能不记录交易流水，因此**无法自动校验"买回价是否真的达到"**。替代做法：

- **先高后低要写三个数**：卖出触发条件、计划买回价、买不回时的处理方式
  （如"波段卖出 300 股 @26.8，计划买回 ≤25.4，不回落则放弃并保留现金"）；
- **先低后高要写另外三个数**：买入价、计划卖出价、卖不掉时的处理方式
  （如"波段买入 300 股 @25.18，计划卖出 26.51，60 日内不达则重设为长期敞口"）；
- 分桶提供了一半的校验：**卖出股数不能超过波段仓**，由 `check-order` 强制执行；
- 另一半（成交价是否真的达到）仍需人工确认——脚本只看你报的数，不看你实际成交价。**如实填写是这条规则成立的前提。**
- **建仓后必须立刻重设分桶**（`set-profile --code X --swing-shares N`）。不重设的话，后面这笔要卖的时候会被「未划分波段仓」直接拦掉——脚本不会替你记这笔买入是波段。

### 7.8 五条命令速查

```bash
# 1) 划分：波段仓 300 股
portfolio.py set-profile --code 600096 --core-shares 800   # 1100 股中 800 为底仓、300 为波段仓

# 2) 先卖后买·第一腿（卖出）：必须同时给出买回价，校验"买回 ≤ 卖价×0.95"
portfolio.py check-order --code 600096 --side sell --shares 300 --limit 26.80 \
  --prev-close 26.50 --sell-reason swing --buyback-price 25.40 --data-fresh

# 3) 先卖后买·第二腿（买回）：加 --swing-buyback 与 --swing-sell-price
#    校验「买回 ≤ 卖价×0.95、≤ fair_high、≤ 上轮卖出股数与回收金额」，豁免建仓通道
portfolio.py check-order --code 600096 --side buy --shares 300 --limit 25.40 \
  --prev-close 26.50 --option-reviewed --fundamental-ok --data-fresh \
  --swing-buyback --swing-sell-price 26.80 --swing-sold-shares 300
#    买回成交后重设分桶（core 不变 → swing 自动派生）

# 4) 先买后卖·第一腿（建仓）：加 --swing-open 与 --target-sell-price
#    豁免建仓通道与矩阵 room_amount，改校验「卖价 ≥ 买价×1.05、卖价 ≤ fair_high、
#    买价 ≤ fair_high÷1.05、金额 ≤ 可用资金」
portfolio.py check-order --code 600096 --side buy --shares 300 --limit 25.18 \
  --prev-close 25.20 --option-reviewed --fundamental-ok --data-fresh \
  --swing-open --target-sell-price 26.51
#    成交后立刻重设分桶：set-profile --code 600096 --swing-shares 300

# 5) 先买后卖·第二腿（兑现）：加 --swing-exit 与 --swing-entry-price
#    不要再填买回价——出口在买入时就定了，这里只验证「卖出价 ≥ 买入价×1.05」
portfolio.py check-order --code 600096 --side sell --shares 300 --limit 26.51 \
  --prev-close 26.20 --sell-reason swing --swing-exit --swing-entry-price 25.18 --data-fresh
```

没有出入两端价格的"波段"会被直接判失败——**没有出口的波段，本质是减仓或摊薄**。同理，**卖出成交到买回成交之间、买入成交到卖出成交之间，这笔操作都仍未闭环**：在另一端成交之前，不要把它记成"波段已完成"。

## 8. 量价五态（尾盘必须五选一）

判断输入：当日 K 线（可含盘中未完成）、近 5 日均量、20 日低点、20/60 日均线、60 日区间位置、上下影线。
用 `volprice` 得到规则化初判，最终**人工确认一个标签**，与初判不同须写明理由。

| 标签         | 量化特征                                     | 动作倾向                           |
| ---------- | ---------------------------------------- | ------------------------------ |
| **放量破位**   | 量比 ≥1.5，跌破 20 日低点 / 20 或 60 日均线，跌幅 ≤ −3% | 不加仓；若同时触发 A 类信号才减仓。单日跌幅本身不构成卖出 |
| **放量反包**   | 量比 ≥1.5，收盘吞没前一日实体，涨幅 ≥ +3%               | 不追高；只在仍处于建仓通道时按节奏执行            |
| **缩量止跌**   | 量比 ≤0.8，未创 5 日新低，跌幅收敛或下影 ≥40%            | 观察，可在通道价位挂限价单等成交               |
| **缩量阴跌**   | 量比 ≤0.8，创 5 日新低，5 日累计跌幅 ≤ −3%            | 不动。缩量阴跌是"没人接"，不是"见底"           |
| **高位放量滞涨** | 量比 ≥1.5，60 日区间位置 ≥80%，涨幅 ≤1.5% 或上影 ≥40%  | 警戒；若在透支区，按 B 类减仓；若在做波段，这正是卖出触发 |

**量价只决定"什么时候动手、动多少"，永远不能单独决定"是否卖出底仓"**。放量破位而基本面完好时，正确动作是"不动或等待建仓通道"，不是止损。

## 9. 硬约束（全局，任何一笔订单都过）

以下是**两条策略共用**的底线，不涉及任何一方的进场逻辑：

1. 股数 > 0 且为每手整数倍（港股按 `quote.lot`）。
2. **上行期权已评估**：必须显式确认，无可定价期权也要写"无"，不允许跳过（跳过等于假设公司不会变好）。
3. A 股限价在 `[price_floor, price_ceiling]` 内；港美股限价偏离昨收 ≤10%（防误填）。
4. 卖出股数 ≤ 持股数。
5. 行情数据为当日且已核对时间戳。
6. 不融资、不加杠杆、不挪用其他标的的资金。
7. 单笔买入金额 ≤ 该标的可用资金。

**以下三条只约束底仓，不适用于波段**（放在 6.4 里，此处仅提示不要误用）：
· 价格必须落在 A/B/C 某一建仓通道内；· 限价 ≤ `fair_high_price`；· 额度取自 `matrix.room_amount`。

**以下两条只约束底仓卖出，不适用于波段兑现**：
· 卖出理由 ∈ {基本面恶化, 估值透支}；· 以"估值透支"为由时，卖出价必须 ≥ `overvalued_above_price`。

任一 fail，该笔**不可执行**，输出必须写明"不满足，放弃该笔"。用 `check-order` 生成校验表，不要口算。

## 10. 尾盘纪律（每条尾盘输出末尾原样引用）

> 尾盘是新信息最少的时段，绝大多数日子正确答案是什么都不做。

配套要求：

- 建议交易时必须回答"为何不能明早再做"。除以下情形，交易推迟到次日 9:30 后的完整交易时段：
  ① 价格已触及 `overvalued_above_price` 且触发 B 类减仓纪律；
  ② 当日已证实的基本面事件（公告、监管处罚、业绩预告变脸）改变了对企业的判断；
  ③ 波段的目标价当日已触及且需要当日兑现（此时回答"为何不能明早再做"＝"目标价是今天给的，明天可能反向"）。
- 尾盘涨跌幅属于当日已知信息，**不构成明日预测**，不得用"今天跌了所以明天还会跌"作为理由。
- 尾盘禁止的行为：为摊薄成本加仓、追已涨停/大涨的标的、因浮亏恐慌卖出、把"今天不动"改写成"明天必须动"。

## 11. 防错自检（每次输出前过一遍）

1. 结论里是否出现"跌了""亏了""怕"这类情绪依据？→ 有则删除重写。
2. 每个数字是否有来源与时间戳？
3. 是否把技术面结论当成买卖理由？
4. **是否先做了第 5 节的分流？** 报告的"本次性质"写的是建仓还是波段？
5. 若结论是"动"，是否逐条核对了第 9 节硬约束，以及对应策略块自己的校验？
6. 若结论是"不动"，是否说明了"什么条件下才会动"？
7. **若标的长期空仓且质地 ≥8：是否检查过"时间换价格"通道（6.2 的 C）？还是一直在等一个不会来的价格？**
8. **若已建仓且 6.1 两类理由都不成立：是否给了波段建议，而不是只写"不能再加仓"就收尾？**
9. **若给了波段条件：有没有误用建仓通道、`room_amount` 或预算使用度？** 三者任一出现即为混淆。
10. **若给出了买入价位（底仓）：它是 `calc` 哪个字段？距现价多少？跌超 15% 的价位，是否已标注为「尾部机会」而不是「下一步」？** 没写来源的价格一律删掉重写——即兴价格比没有价格更有害。
11. **若建议卖出：是 6.1 的理由，还是隐含地因为"涨太多"？透支线是否已含期权？**
12. 与上一次 `last-log` 的结论是否矛盾？矛盾时解释变化的新事实。
